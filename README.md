# 📖 Книга пожеланий моделей

**Что это:** единый файл, куда любая модель/чат (Copilot в VS Code, Claude Code, Cowork, Roo, Continue) может записать:
- чего ей не хватает (инструменты, MCP, плагины, доступы, скиллы),
- что работает плохо и что починить,
- что внедрено и проверено.

**Правила:**
1. Записи добавляются в конец соответствующего раздела, с датой и именем поверхности.
2. Статусы: `🆕 предложено` → `👀 на рассмотрении` → `✅ внедрено` / `❌ отклонено` (с причиной).
3. Макс просматривает файл периодически и решает, что внедрять. Внедрив — меняет статус.
4. Файл лежит в `ZAI` и опубликован: **https://github.com/alfagang838/agent-wishlist**

8. **🎫 ТИКЕТЫ (новое, 25.08.2026)**. Нашёл проблему, чинить которую не вправе — открывай тикет, а не абзац в отчёте, который никто не перечитает. **Тикет не заменяет починку**: можешь починить сам — чини (Р21). Тикет ровно для четырёх случаев: нужен доступ или решение Макса; живой прод; отмена чужого решения; чужой проект, куда сейчас не лезешь.
   ```
   select public.ticket('проект','bug','заголовок','что нашёл',
     'чем проверено: файл:строка / запрос / прогон',
     'ГОТОВЫЙ ПРОМПТ — Макс вставит его в терминал как есть','high');
   ```
   Обязательны `evidence` (без доказательства это слух) и `agent_prompt` — самодостаточный текст с путями к файлам и проверкой после. Открытые: `select * from public.v_open_tickets;`. Закрыть: `select public.ticket_done(id,'чем закрыто')` — без основания база не даст. Смысл: Макс видит тикет в админ-панели, копирует промпт, вставляет в терминал любому агенту — тот чинит без переспрашиваний.
   **Границы, чтобы не плодить дубли:** тикет = находка в проекте; `public.handoffs` = передача хвоста второй ИИ-поверхности; эта книга = пожелания к инструментам и доступам; `public.tasks` = задачи Макса, агентскими находками не засорять.
